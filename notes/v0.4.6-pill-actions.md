# Dank Lookup v0.4.6: pill + utility actions

Goal: replace the empty segmented row with a compact pill and two utility actions when only one dictionary mode is available.

## Problem

v0.4.5a hides segments not in `available_modes`. When only one mode returns results (e.g. han-en removed via config, or a kana query that only has ja), the segmented row becomes a single unclickable segment — it wastes vertical space and offers no switching value.

This is especially visible with the experimental han + en-en only config.

## Design

### Mode pill (single mode)

When `availableModes.length === 1`, show a compact pill instead of the segmented row:

```
┌─────────────────────────────┐
│  ✕  consolidate             │
│   [ 英英 ]  C  F            │   ← mode pill + Copy + Open full
│  dictd_www.dict.org_gcide   │
│ ─────────────────────────── │
│  Consolidate \Con*sol"...   │
└─────────────────────────────┘
```

- Pill shows the current mode label (e.g. `英英`, `日語`, `粵語`).
- Two small action buttons next to the pill: Copy (C) and Open full (F).
- Avoid emoji icons in final QML; use text labels or DMS-themed icons if available.

### Segmented row (multi mode)

When `availableModes.length > 1`, the existing segmented row is shown unchanged.

### Copy action

Copies `resultBody` (plain definition text) to the clipboard. Local only — no network, no web API.

Implementation candidates: `wl-copy` shell out, or Qt clipboard API.

### Open full action

Writes `resultBody` to `/tmp/dank-lookup/full.txt` and opens it in an external viewer. The viewer command is configurable via `config.json`:

```json
{
  "actions": {
    "open_full_command": "ghostty --class=floating -e less"
  }
}
```

Default: `xdg-open /tmp/dank-lookup/full.txt`. Future presets: `ghostty`, `foot`, `kitty`.

## Acceptance

- `consolidate` under en-en-only config → pill `[英英]` + Copy / Open full buttons.
- `字典` under han + en-en config → pill `[漢語]` + buttons.
- Default 3-mode config (han / han-en / en-en) → full segmented row, no pill.
- Copy writes `resultBody` to clipboard; does not include JSON metadata.
- Open full spawns external viewer; does not block the lookup popup.
- No new daemon, no polling increase, no network request.

## Open questions (recorded, not solved)

1. Should Open full use `xdg-open`, a terminal pager (`less`), or an expanded DMS-native panel?
2. Should copied text include the source name (e.g. `[WordNet]`) or only the definition body?
3. Should the action row be visible on hover only, or always visible?

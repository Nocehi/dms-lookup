# Dank Lookup v0.5.0a: QML button refactor handoff

This is an implementation handoff for opencode.

The purpose of v0.5.0a is to prove the `T.Button + state object` pattern on a
small, reversible slice of `DankLookup.qml`. Do not refactor the whole popup in
one pass.

## Current problem

`DankLookup.qml` still has several hand-built controls:

```text
Rectangle
  Text
  MouseArea
```

This pattern appears in:

| Control | Current location |
|---------|------------------|
| Close button | `DankLookup.qml`, around line 239 |
| Pill Copy button | `DankLookup.qml`, around line 289 |
| Pill Open-full button | `DankLookup.qml`, around line 311 |
| Segmented row buttons | `DankLookup.qml`, around line 343 |
| Related toggle | `DankLookup.qml`, around line 420 |

The visual result is currently acceptable. The problem is maintainability:

- hover colors are repeated inline
- size/radius values are repeated inline
- behavior and visual state are mixed into layout code
- future button variants will copy more `Rectangle + MouseArea` blocks

## Design direction

Use Qt's official custom-control shape:

```qml
import QtQuick.Templates as T

T.Button {
    contentItem: Text { }
    background: Rectangle { }
}
```

Keep DMS as the theme source:

```qml
Theme.primary
Theme.surfaceText
Theme.onPrimary
Theme.withAlpha(...)
```

Do not import QmlMaterial. QmlMaterial and Qt Material style are only references.

## Scope for v0.5.0a

Migrate only these controls:

1. Close button.
2. Pill Copy button.
3. Pill Open-full button.

Do not migrate in this version:

- segmented row
- Related toggle
- body typography
- title typography
- popup layout
- backend/file signal logic

This keeps the patch small enough to visually verify.

## Component 1: `DankIconButton.qml`

Use this for the close button.

### API

```qml
DankIconButton {
    text: "\u2715"
    onClicked: popup.visible = false
}
```

### Required behavior

| Property | Value |
|----------|-------|
| implicit width | `28` |
| implicit height | `28` |
| radius | `14` |
| rest background | `transparent` |
| hover background | `Theme.withAlpha(Theme.primary, 0.30)` |
| text color | `Theme.surfaceText` |
| text size | `14` |
| cursor | pointing hand |

### Suggested implementation shape

```qml
import QtQuick
import QtQuick.Templates as T
import qs.Common

T.Button {
    id: control

    property alias text: label.text

    implicitWidth: 28
    implicitHeight: 28
    hoverEnabled: true
    cursorShape: Qt.PointingHandCursor

    contentItem: Text {
        id: label
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
        font.pixelSize: 14
        color: Theme.surfaceText
    }

    background: Rectangle {
        radius: 14
        color: control.hovered
            ? Theme.withAlpha(Theme.primary, 0.30)
            : "transparent"
    }
}
```

If `cursorShape` is not available on `T.Button` in this Quickshell/QML version,
keep a local `MouseArea` only inside this helper component. Do not leave
duplicate MouseArea blocks in `DankLookup.qml`.

## Implementation note after local test

The original plan of creating standalone helper components
(`DankIconButton.qml`, `DankPillActionButton.qml`) was attempted but did not
work in the local Quickshell/DMS runtime.

### What was tried

1. Separate QML files in the plugin directory with `DankIconButton` and
   `DankPillActionButton` types.
2. `import "." in DankLookup.qml` to reference them.

### What failed

- Quickshell's QML engine did not resolve local file imports (`import "."`).
  Tested with dms reload → `PLUGIN_RELOAD_FAILED: DanIconButton is not a type`.
- `T.Button` in Quickshell does not expose `cursorShape` as a property.
  Tested with: `Cannot assign to non-existent property "cursorSha"`.

### What works (current implementation)

- All button code is written inline as `T.Button { }` blocks in `DankLookup.qml`.
- Three inline instances: close button (✕), Copy button (C), Open-full button (F).
- `import QtQuick.Templates as T` is at the top of `DankLookup.qml`.
- Cursor feedback is provided by a transparent `MouseArea` shim inside each
  `T.Button`:

```qml
MouseArea {
    anchors.fill: parent
    cursorShape: Qt.PointingHandCursor
    acceptedButtons: Qt.NoButton
    hoverEnabled: true
}
```

- This is a pointer-cursor shim, not a return to the `Rectangle + MouseArea`
  control pattern. T.Button handles all click events; the MouseArea only
  provides cursor feedback.

### Remaining from v0.5.0 proposal

- Segmented row buttons still use `Rectangle + MouseArea` (not migrated).
- Related toggle still uses `Rectangle + MouseArea`.
- Typescale centralization is not implemented.
- The `DankIconButton.qml` and `DankPillActionButton.qml` files were removed
  in v0.5.0b cleanup.

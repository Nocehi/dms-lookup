# Dank Lookup v0.4.7b: test infrastructure cleanup

## Problem

The backend writes all lookup results to a shared file:

```
/tmp/dank-lookup/backend_result.json
```

For UI usage this is fine — the popup is single-threaded and sequential. But for
testing, the shared file creates a race condition:

- Two backend calls cannot run in parallel (e.g. fixture A + manual lookup)
- The fixture runner and a concurrent `Mod+Alt+D` invocation collide
- Adding more fixtures (e.g. ja/yue) makes this worse because the runner takes
  longer and collisions become more likely

A second concern: the current four core fixtures test `han`, `han-en`, `en-en`
behavior. With ja/yue now deployed, ja/yue tests must not depend on dictionaries
that not every user will have. They should be a separate, optional fixture set.

## Proposed solution

### Part 1: `DANK_LOOKUP_OUTPUT` env var (1 line in sdcv.sh)

The backend already uses a shell redirect to write the output:

```bash
python3 -c '...' "$query" > "$out_dir/backend_result.json"
```

A bash variable is set at the top, defaulting to the standard path:

```bash
out_file="${DANK_LOOKUP_OUTPUT:-$out_dir/backend_result.json}"
```

Both the mock fallback (line 13) and the real output (line 234) redirect to
`$out_file`. When `DANK_LOOKUP_OUTPUT` is not set, behavior is identical to
today — the UI continues to read the default path. No changes needed in:
- `dank-lookup-selection` (uses default path)
- `DankLookup.qml` (reads default path)
- Python block (output goes to `sys.stdout`, shell redirect handles the file)

### Part 2: Per-test output isolation in runner

The fixture runner calls the backend once per test, then reads the output.
With `DANK_LOOKUP_OUTPUT`, each test writes to its own file:

```text
/tmp/dank-lookup/fixture-consolidate.json
/tmp/dank-lookup/fixture-linux.json
/tmp/dank-lookup/fixture-request.json
/tmp/dank-lookup/fixture-why.json
/tmp/dank-lookup/fixture-haiku-ja.json
/tmp/dank-lookup/fixture-nihongo-ja.json
/tmp/dank-lookup/fixture-qualify-yue.json
/tmp/dank-lookup/fixture-dictionary-yue.json
```

Benefits:
- Fixtures can run truly sequentially (no file collision)
- Manual testing at `Mod+Alt+D` does not interfere with test output
- A future parallel fixture runner is safe
- Temp files are in tmpfs, cleared on reboot

### Part 3: ja/yue optional fixture set

New fixture directory:

```
tests/fixtures-ja-yue/
  haiku-ja.json
  nihongo-ja.json
  dictionary-ja.json
  qualify-yue.json
  dictionary-yue.json
  spring-yue.json
```

These fixtures test that deployed ja/yue dictionaries return expected results,
but they are NOT run by default in the core fixture suite. Run them explicitly:

```bash
python3 tests/run_backend_fixtures.py tests/fixtures-ja-yue
```

Or with the current local path:

```bash
python3 ~/.local/lib/dank-lookup/tests/run_backend_fixtures.py \
  ~/.local/lib/dank-lookup/tests/fixtures-ja-yue
```

Core baseline remains 4/4 expected for default config.

## Simple solution vs clean solution

| Aspect | Simple (runner-side) | Clean (DANK_LOOKUP_OUTPUT) |
|--------|---------------------|---------------------------|
| Changes | runner only | backend (1 line) + runner |
| Race with manual lookup | Still exists | Eliminated |
| Parallel fixture support | No | Yes |
| Code complexity | busy-wait + timeout | one env var read |
| Backward compat | Full | Full (default path unchanged) |

The clean solution is recommended because:
- It eliminates the race at the source, not just in one consumer
- The change is smaller than adding busy-wait logic to the runner
- It naturally enables ja/yue fixtures without collision concerns

## Implementation order

1. **sdcv.sh**: add `DANK_LOOKUP_OUTPUT` support (1 line)
2. **run_backend_fixtures.py**: use per-test output path, remove shared file
3. **fixtures-ja-yue/**: create new fixture files for ja/yue behavior
4. **README**: document ja/yue fixture command for local verification

## Rollback

To restore the `sdcv.sh` bash redirect to the hardcoded path:

```bash
# Revert the out_file variable to the fixed path in sdcv.sh:
#   out_file="${DANK_LOOKUP_OUTPUT:-$out_dir/backend_result.json}"
# → out_file="$out_dir/backend_result.json"
```

To revert the fixture runner to shared-file mode, restore the previous
`run_backend_fixtures.py` that reads from the shared `OUT` path directly.
The ja/yue fixture directory can remain or be removed independently. No
dictionary data or QML files are affected by this rollback.

```bash
git checkout -- ~/.local/lib/dank-lookup/backends/sdcv.sh
git checkout -- ~/.local/lib/dank-lookup/tests/run_backend_fixtures.py
```

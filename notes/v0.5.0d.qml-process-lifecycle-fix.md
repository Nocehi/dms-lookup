# Dank Lookup v0.5.0d: QML Process lifecycle fix

## Problem

Two QML functions create a `Quickshell.Io.Process` instance, write the
definition body to stdin via `p.write(resultBody)`, but never close stdin
after writing. Without an EOF signal, the subprocess (wl-copy or cat) may
hang waiting for more input.

## Investigation

Quickshell Process API read from `/usr/lib/qt6/qml/Quickshell/Io/quickshell-io.qmltypes`:

- No `close()`, `destroy()`, or `closeWriteChannel()` method exists on Process.
- The API has `stdinEnabled` (bool) with a setter `setStdinEnabled(false)`.
- Setting `stdinEnabled = false` closes the stdin channel, propagating EOF
  to the subprocess.
- This is the correct Quickshell API for signaling EOF to stdin.

## Changes

File: `DankLookup.qml` — two functions changed:

### copyToClipboard()

```qml
var p = Qt.createQmlObject(
    'import Quickshell.Io; Process { command: ["wl-copy"]; running: true; stdinEnabled: true }',
    root
)
Qt.callLater(function() {
    p.write(resultBody)
    Qt.callLater(function() { p.stdinEnabled = false })
})
```

### openFullSource()

```qml
var p = Qt.createQmlObject(
    'import Quickshell.Io; Process { command: ["sh", "-c", "cat > /tmp/dank-lookup/full.txt && xdg-open /tmp/dank-lookup/full.txt"]; running: true; stdinEnabled: true }',
    root
)
Qt.callLater(function() {
    p.write(resultBody)
    Qt.callLater(function() { p.stdinEnabled = false })
})
```

Both changes:
- Add `stdinEnabled: true` to the Process initialization.
- Wrap `p.write(resultBody)` in `Qt.callLater` to let the process start first.
- Add a second `Qt.callLater` to set `stdinEnabled = false` after writing,
  which closes stdin and signals EOF.

# Dank Lookup v0.5.0: QML button and typescale refactor

## Motivation

The current `DankLookup.qml` has four visual control patterns that are hand-built
from `Rectangle` + `Text` + `MouseArea` with inline color/geometry bindings.

As the QML grows (pill C/F buttons, segmented row, close button, Related toggle),
these inline bindings become harder to maintain and visually inconsistent.

QmlMaterial (hypengw/QmlMaterial, MIT) and Qt Quick Templates demonstrate a
cleaner pattern: **state-per-control** — a dedicated object computes all visual
values from the control's properties, separating design computation from layout.

This proposal adapts the same idea in pure QML, without the C++ dependency and
without importing QmlMaterial itself.

## What changes

| Control | Current | Proposed |
|---------|---------|----------|
| Pill C/F buttons | `Rectangle` + `MouseArea` | `T.Button` + `DankButton.State` |
| Segmented row segments | `Repeater` + `Rectangle` + `MouseArea` | `T.Button` + `DankSegmented.State` |
| Close button (✕) | `Rectangle` + `MouseArea` | `T.Button` + `DankIconButton.State` |
| Related toggle | `Rectangle` + `MouseArea` | `T.Button` + `DankToggle.State` |
| Text elements | scattered pixelSize | centralized `DankTypescale` roles |

## What stays unchanged

- DMS Theme tokens (`Theme.primary`, `Theme.surfaceText`, etc.)
- File-based IPC (`/tmp/dank-lookup/*.json`)
- Backend (`sdcv.sh`, `dank-lookup-selection`)
- QML layout structure (`FloatingWindow`, `Column`, `Flickable`, source label, body)
- Dark/light theme switching (handled by DMS)
- No C++ dependency, no QmlMaterial import, no new build step

## State-per-control pattern

The core idea: each control type has a companion `QtObject` that computes visual
values based on the control's runtime properties (hovered, pressed, enabled,
active, etc.).

```qml
// DankButtonState.qml — computed design values for pill buttons
QtObject {
    id: root

    property T.Button item

    readonly property color textColor: item.hovered
        ? Theme.primary : Theme.surfaceText
    readonly property color bgColor: item.hovered
        ? Theme.withAlpha(Theme.primary, 0.15) : "transparent"
    readonly property int radius: 8
    readonly property int containerSize: 26
}
```

Using it in a T.Button:

```qml
T.Button {
    id: control

    property DankButtonState ds: DankButtonState { item: control }

    implicitWidth: ds.containerSize
    implicitHeight: ds.containerSize

    contentItem: Text {
        text: "C"
        color: control.ds.textColor
        font.pixelSize: 11
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
    }

    background: Rectangle {
        radius: control.ds.radius
        color: control.ds.bgColor
    }
}
```

## State objects

### DankButton.State (for pill C/F buttons)

```
┌─────────────────────────────────────────────┐
│ Properties: (none — icon/text-only variants) │
│ Computes:                                    │
│   textColor: hovered → primary, else surface │
│   bgColor:   hovered → primary@0.15, else tr │
│   containerSize: 26                          │
│   radius: 8                                  │
└─────────────────────────────────────────────┘
```

### DankSegmented.State (for segment row buttons)

```
┌─────────────────────────────────────────────┐
│ Properties:                                  │
│   isActive:  modelData === root.activeMode   │
│   length:    root.availableModes.length      │
│ Computes:                                    │
│   textColor:  active → onPrimary, else surfa │
│   bgColor:    active → primary, else transpa │
│   width:      (segmentedRow.width - spacings │
│               / length                       │
│   height: 34                                 │
│   radius: 9                                  │
└─────────────────────────────────────────────┘
```

### DankIconButton.State (for close ✕)

```
┌─────────────────────────────────────────────┐
│ Properties: (none)                           │
│ Computes:                                    │
│   textColor: hovered → primary, else surface │
│   bgColor:   hovered → primary@0.10, else tr │
│   containerSize: 28                          │
│   radius: 8                                  │
└─────────────────────────────────────────────┘
```

### DankToggle.State (for Related toggle)

```
┌─────────────────────────────────────────────┐
│ Properties:                                  │
│   isActive:  root.showRelated                │
│ Computes:                                    │
│   textColor:  active → primary, else surface │
│   underline:  visible when active            │
│   height: 24                                 │
└─────────────────────────────────────────────┘
```

## Centralized typescale

Replace scattered pixelSize values with named typescale roles:

```qml
// At the root of DankLookup.qml
readonly property QtObject ts: QtObject {
    readonly property QtObject title: QtObject {
        readonly property int size: root.hasCjkOrKana(root.queryText) ? 26 : 24
        readonly property real lineHeight: 1.12
        readonly property int weight: Font.Normal
    }
    readonly property QtObject bodyLatin: QtObject {
        readonly property int size: 14
        readonly property real lineHeight: 1.42
        readonly property int weight: Font.Normal
    }
    readonly property QtObject bodyCjk: QtObject {
        readonly property int size: 15
        readonly property real lineHeight: 1.50
        readonly property int weight: Font.Normal
    }
    readonly property QtObject source: QtObject {
        readonly property int size: 11
        readonly property real lineHeight: 1.0
        readonly property int weight: Font.Normal
    }
    readonly property QtObject segment: QtObject {
        readonly property int size: 12
        readonly property real lineHeight: 1.0
        readonly property int weight: Font.Medium
    }
    readonly property QtObject pill: QtObject {
        readonly property int size: 11
        readonly property real lineHeight: 1.0
        readonly property int weight: Font.Normal
    }
}

// Usage example:
Text {
    font.pixelSize: root.ts.title.size
    font.weight: root.ts.title.weight
    lineHeight: root.ts.title.lineHeight
}
```

This makes typography consistent across modes and queries, and makes it easy to
adjust all instances of a role at once.

## Refactoring plan

### Phase 1: state objects only (new helper QML files)

Create `~/.config/DankMaterialShell/plugins/dankLookup/DankButtonState.qml` and
related state files (e.g. `DankSegmentedState.qml`). This is pure QML — no
template imports, no C++.

Each file is ~30 lines.

### Phase 2: migrate one control at a time

| Step | Control | Effort |
|------|---------|--------|
| 1 | Pill C/F buttons | ~20 lines replaced |
| 2 | Close (✕) button | ~15 lines replaced |
| 3 | Related toggle | ~15 lines replaced |
| 4 | Segmented row segments | ~30 lines replaced |
| 5 | Text elements → typescale roles | ~10 property references |

Each step is independent and can be verified by reloading the plugin.

### Phase 3: cleanup old inline bindings

After all four controls and text elements use state-per-control patterns, remove
the old dead `Rectangle` + `MouseArea` + inline binding code.

## Acceptance

- Plugin reloads without QML parse error.
- Pill buttons show correct hover/rest colors.
- Segmented row segments render at correct widths and colors.
- Close button, Related toggle, and source label remain visually unchanged.
- 18/18 fixtures still pass.
- No new shared file races in tests.
- No network request, no daemon.

## Non-goals

- Do not import QmlMaterial (hypengw/QmlMaterial).
- Do not add Ripple animation (not needed for small icon buttons).
- Do not rebuild the card layout or IPC model.
- Do not change backend or dictionaries.
- Do not change the QML `import` approach or build system.

## References

### Code pattern references

- QmlMaterial Button.qml — `T.Button` + `StateButton` pattern (MIT, hypengw)
- QmlMaterial Text.qml — typescale-centralized text (MIT, hypengw)
- Qt Quick Templates: `T.Button`, `T.Label` (LGPL, bundled with Qt 6.8+)

### Qt Material style (official reference)

Qt's own `QtQuick.Controls.Material` style implements buttons using the same
architecture this proposal targets:

```
T.Button (QtQuick.Templates)
├── contentItem: IconLabel
├── background: Rectangle + RoundedElevationEffect + Ripple
└── Material.* attached properties → color, elevation, roundedScale
```

Qt documentation states that custom QML style files should use the corresponding
`QtQuick.Templates` type as root item. This validates the `T.Button` approach
taken by QmlMaterial and proposed here.

Reference: `qt/qtdeclarative` — Qt Quick Controls Material style implementation.

### AvengeMedia/DankMaterialShell (platform reference)

Since dankLookup runs as a DMS plugin, the most concrete architecture reference
is DMS itself, not an abstract library:

```
DankMaterialShell/
└── quickshell/
    ├── Modules/     UI components (panels, widgets, overlays)
    ├── Services/    System integration (audio, network, bluetooth)
    ├── Widgets/     Reusable UI controls
    └── Common/      Shared resources and themes
```

DMS already provides the `Theme.*` tokens (primary, surfaceText, etc.) that
dankLookup uses. The v0.5.0 refactor keeps these as the sole color source —
it does not add a separate theme engine.

The DMS repo structure also shows how to organize reusable QML components
within a shell project. If state objects grow beyond inline helpers, they can
follow DMS's `Common/` pattern rather than living in the plugin directory.

# Dank Lookup v0.4.9: risk hardening

This document is a handoff for opencode. The goal is to reduce release and
maintenance risk without changing the product direction.

v0.4.8 confirmed the current routing behavior with fixtures. v0.4.9 should be a
small hardening pass before broader features such as Big Bang segmentation,
network sources, or extra language packs.

## Current state

Dank Lookup is now usable as a local DMS/niri lookup tool:

- Selection script reads primary selection, then clipboard fallback.
- Backend is config-driven and uses `sdcv`.
- QML popup supports Material-style card layout, mode switching, and v0.4.6
  pill/actions.
- Current fixture coverage is split into:
  - core fixtures
  - ja/yue deployment fixtures
  - reading-routing fixtures
- Repo copy intentionally excludes dictionary data.

The remaining risks are not feature blockers, but they matter before publishing
or asking other users to try the project.

## Goals

1. Make dictionary redistribution boundaries explicit.
2. Prevent unknown text from being misclassified as Japanese/kana.
3. Separate CI-ready tests from local dictionary-dependent tests.
4. Add a lightweight pre-release checklist that can be run before packaging.

## Non-goals

- Do not implement Big Bang segmentation in this version.
- Do not add network translation, Wikipedia, LLM, or OCR.
- Do not bundle dictionary files.
- Do not rewrite the QML popup.
- Do not replace the file-based signal mechanism yet.

## Risk 1: dictionary licensing and redistribution

### Problem

Several useful local dictionaries are suitable for personal use but should not
be redistributed in the repository.

Known local sources:

| Source | Current role | Release handling |
|--------|--------------|------------------|
| `words.hk 粵語詞典` | yue mode | Do not redistribute CSV or converted StarDict files |
| `XDICT英漢辭典` | bilingual fallback / local testing | Do not redistribute unless license is verified |
| `XDICT漢英辭典` | bilingual fallback / local testing | Do not redistribute unless license is verified |
| `reader.dict JA` | ja mode | Do not redistribute unless license is verified |
| `萌典重編國語辭典` | han mode | Link to upstream/license, do not silently repackage |
| `GCIDE` | en-en mode | Safe to document as installable source when license is noted |
| `WordNet` | en-en mode | Safe to document as installable source when license is noted |
| `FreeDict/WikDict` | optional bilingual fallback | Safe only when upstream license and package source are noted |

The repo must not contain:

```text
*.ifo
*.idx
*.dict
*.dict.dz
*.syn
*.csv
converted StarDict output from restricted sources
```

### Required changes

Create a release-facing source note:

```text
docs/dictionary-sources.md
```

Minimum content:

- Explain that Dank Lookup is code-only by default.
- Explain that users install dictionaries separately.
- List safe install paths:

```bash
mkdir -p ~/.local/share/stardict/dic
```

- Explain that `sdcv` can read:

```text
/usr/share/stardict/dic
${XDG_DATA_HOME:-~/.local/share}/stardict/dic
STARDICT_DATA_DIR
```

- Mark each known source as one of:
  - `redistributable`
  - `user-installed only`
  - `unknown, do not redistribute`
  - `local experiment only`

### README addition

Add a short release safety note to both:

```text
README.md
plugin/README.md
```

Suggested wording:

```markdown
Dank Lookup does not ship dictionary data. Some dictionaries that work locally
may not be redistributable. Install dictionaries yourself and check each
source's license before sharing converted StarDict files.
```

## Risk 2: unknown text classification

### Problem

Current backend classification ends with:

```python
return "kana"
```

That means non-CJK, non-Latin, non-kana input can be treated as Japanese/kana.
Examples:

```text
🙂
--
12345
@
```

This is low risk in daily use, but it is semantically wrong and can make future
fallback logic harder to reason about.

### Required behavior

Change the fallback class to:

```python
return "unknown"
```

Expected classification policy:

| Query | Class |
|-------|-------|
| `consolidate` | `latin` |
| `Linux` | `latin` |
| `為甚麼` | `cjk` |
| `俳句` | `cjk` |
| `日本語` | `cjk` or `kana` depending exact implementation |
| `かな` | `kana` |
| `ネット` | `kana` |
| `C語言` | `mixed` |
| `🙂` | `unknown` |
| `12345` | `unknown` |
| `--` | `unknown` |

For `unknown`, the backend should either:

1. Return a structured no-result response, or
2. Use the existing mock/no-result fallback.

It should not choose `ja` only because the input is unknown.

### Fixture additions

Add a small optional fixture set:

```text
tests/fixtures-risk-hardening/
  unknown-emoji.json
  unknown-number.json
  unknown-punctuation.json
```

Each fixture should assert:

- backend exits successfully
- `default_mode` is not `ja`
- result is either empty/no-result or a clear fallback
- no exception text appears in body

If the existing fixture runner cannot express `default_mode != ja`, extend the
runner with `default_mode_not` or `not_equals` support.

## Risk 3: local-only fixtures vs CI-ready fixtures

### Problem

The current fixture suite includes tests that depend on locally installed
dictionaries:

- `words.hk 粵語詞典`
- `reader.dict JA`
- `萌典重編國語辭典`
- XDICT dictionaries

That is correct for this machine, but not portable. A future public repo should
not make a new user fail tests just because they did not install private or
license-unclear dictionaries.

### Required split

Document and enforce two levels:

| Level | Purpose | Expected environment |
|-------|---------|----------------------|
| `fixtures-ci-minimal` | CI-ready smoke test | only en-en redistributable/system dictionaries (GCIDE + WordNet) |
| `fixtures` | local baseline verification | requires full local config (萌典, XDICT) |
| `local` | nocehi machine verification | all optional fixture sets |

Recommended commands:

```bash
# CI-safe baseline (portable — only needs GCIDE + WordNet)
DANK_LOOKUP_CONFIG=tests/configs/ci-minimal.json \
  python3 tests/run_backend_fixtures.py tests/fixtures-ci-minimal

# Local baseline (requires full local dictionary set)
DANK_LOOKUP_CONFIG=/tmp/dank-lookup-no-such-config.json \
  python3 tests/run_backend_fixtures.py tests/fixtures

# Local full verification
python3 tests/run_backend_fixtures.py tests/fixtures-ja-yue
python3 tests/run_backend_fixtures.py tests/fixtures-reading-routing
python3 tests/run_backend_fixtures.py tests/fixtures-risk-hardening
```

### Required files

Add a minimal CI config:

```text
tests/configs/ci-minimal.json
```

It should only reference dictionaries that can reasonably be installed by a
package manager or documented with clear license:

- `dictd_www.dict.org_gcide`
- `WordNet`

Do not require words.hk, XDICT, reader.dict JA, or local converted dictionaries
in this config.

## Risk 4: pre-release hygiene

### Problem

Before pushing to GitHub, the repo needs a repeatable check that catches common
mistakes:

- absolute local paths
- bundled dictionaries
- runtime JSON/tmp files
- shell syntax errors
- missing license/changelog

### Required script

Add:

```text
packaging/pre-release-check.sh
```

It should check:

```bash
# no hardcoded personal home path in release code
grep -R '/home/nocehi' bin lib plugin packaging

# no dictionary data
find . \( -name '*.ifo' -o -name '*.idx' -o -name '*.dict' -o -name '*.dict.dz' -o -name '*.syn' \)

# no runtime tmp output
find . -path '*/tmp/*' -o -name 'latest.json' -o -name 'backend_result.json'

# shell syntax
bash -n bin/*
bash -n lib/backends/*
bash -n packaging/*.sh

# required release files
test -f LICENSE
test -f CHANGELOG.md
test -f README.md
```

The script should be read-only and exit non-zero on failure.

## Risk 5: file-based signal

### Current assessment

The current QML polling model is acceptable for local use:

- `Timer` interval is low-frequency enough for desktop use.
- `running: !popup.visible` stops polling while the popup is shown.
- There is no clipboard polling, network call, or daemon.

However, it is not a full IPC system:

- no acknowledgement
- no ordering guarantee for rapid repeated lookup
- no push notification
- possible race if a file is read while being replaced incorrectly

### v0.4.9 action

Do not replace it in v0.4.9.

Only document the limitation in README:

```markdown
Dank Lookup currently uses a local file signal under `/tmp/dank-lookup`.
It is designed for user-triggered single lookups, not high-frequency event
streams.
```

IPC replacement can be considered later if DMS exposes a stable plugin-facing
IPC type.

## Rollback

This version should be easy to revert because most changes are documentation,
fixtures, or release tooling.

Runtime rollback:

```bash
# restore only if classify fallback causes unexpected behavior
git checkout -- lib/backends/sdcv.sh
```

Documentation/tooling rollback:

```bash
git checkout -- docs/dictionary-sources.md
git checkout -- packaging/pre-release-check.sh
git checkout -- tests/configs/ci-minimal.json
git checkout -- tests/fixtures-risk-hardening
```

For the live local installation, restore from the synced repo copy only after
checking diffs.
